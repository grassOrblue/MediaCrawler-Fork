# MediaCrawler 本地部署

## 统一研究入口（2026-11-10）

首页现直接进入 http://127.0.0.1:8080/research 。旧采集控制台的 App 源码保留，原根地址、`/index.html`、`/static/index.html` 均跳转到研究页面；前端旧 HTML 的启动脚本也只挂载研究页面，不再渲染旧控制台。

- “开始研究”统一选择平台复选框、自动/关键词搜索/指定内容/创作者主页。平台选项来自后端能力列表；新增平台适配后可自动显示对应复选框。首批适配仍为小红书、抖音、B站。
- 描述解析会给出采集计划，各平台的关键词建议合并去重后填入一份共享关键词，所有选中平台使用相同内容，可手动修改或追加。目标链接/ID 收在平台标签页中，只显示选中的平台，切换保留输入。探索描述默认搜索，内容或主页链接可自动判断；也可以手动覆盖类型或直接填写目标。“改为手动填写”保留当前表单。纯手动采集不需要模型配置，也不发起AI调用。
- “通用设置”集中保存登录方式、各平台 Cookie、检查和评论数量、子评论、媒体下载、起始页、停止条件、请求频率和保存格式。配置在 `app/config/capture.local.json`，已加入 Git 忽略；Cookie 按平台独立存储，接口和日志隐藏原值。设置应用于后续批次，运行中不能通过页面修改。
- 每个研究批次仍写入本机资料库；另选 JSONL/JSON/CSV/Excel/MySQL/MongoDB 时沿用原生保存实现额外输出新增内容。文件记录携带批次号，JSON/JSONL/CSV 文件名也带批次号。外部数据库沿用本地连接配置。
- “开始研究”下方是可展开的系统控制台，沿用原实时日志、清空/恢复/折叠和停止按钮；日志独立区域滚动，不覆盖其他控件。
- 研究采集需要扫码时，二维码会固定显示在页面弹窗，不再依赖外部图片窗口。每轮等待最多 5 分钟，超时自动刷新后继续等待；平台二维码自身的有效期仍由平台决定，也可手动刷新。二维码获取失败时可重试，或确认跳过此平台，关闭其浏览器并继续下一平台。跳过会保存在平台状态中；全部跳过时批次记为已停止。登录二维码只临时保存，不进入历史日志或报告。
- 失败、部分未完成、停止或重启中断的批次，可在“批次与报告”点击“继续采集（同一批次）”。沿用原批次号、采集配置和累计统计，已完成或主动跳过的平台不重跑；未完成平台补采失败帖子及未完成评论，内容通过 ID 去重追加。新搜索任务会保存关键词、搜索页和页内位置；创作者列表及评论列表可能需重新遍历以定位未完成内容。旧批次没有历史分页断点，也会通过已有 ID 避免重复保存。续采不自动调用 AI，原报告保留材料快照；采集结束后重新预估分析可生成新版报告。首次升级会自动备份为 `library.before-resume-*.sqlite3`。
- 三种采集模式都沿用批次记录与 ID 去重；评论只抓本批新内容，创作者模式受全批次数量上限及重复分页保护约束。B站 BV 链接需先获得 aid 才能按资料库中的实际 ID 判重。

验证使用临时数据库、模拟平台及模拟AI，覆盖自动/手动模式、全局设置、Cookie隔离、原生文件输出、详情去重、分页停止、旧地址跳转和桌面/手机页面。没有运行真实采集、调用付费模型或连接用户的外部数据库。

## 需求研究（2026-11-06）

控制台新增“需求研究”入口，直接访问 http://127.0.0.1:8080/research 。资料库顶部也可以进入批次和报告页面。

描述既可以针对某个产品，也可以是“我还不知道要做什么，想看看大家在吐槽哪些日常物品”。探索场景不要求先选产品，AI 会生成发现物品使用问题的关键词，并在报告中按“物品＋具体问题”归类；仍需根据采集样本和原文判断结果，不能视为全网需求总量。

新批次号按北京时间生成为 `YYYYMMDD-HHmmss`，同一秒创建会添加 `-02` 等序号。批次名称留空时使用该编号，也可以自定义名称；已有批次编号及报告链接保留。资料库最上方提供批次下拉，按最新到最早列出全部研究批次，普通打开页面默认选中最新批次；从旧报告打开时则选中链接指定的批次。切换后立即筛选，刷新保留手动选择，导出使用当前批次；也可选择“全部批次”或“历史未分批内容”。没有批次时继续显示已有资料。

使用顺序：

1. 在“AI设置”配置 DeepSeek、Kimi、豆包或自定义兼容接口，填写 API 地址、Key、已开通的模型名称、上下文和输出上限。可选填写每百万 token 的人民币单价。模型版本、价格不写死；豆包可以填写控制台中的模型或接入点 ID。
2. 在“开始研究”描述产品、场景和想了解的问题，选择小红书、抖音、B站。点击“预估关键词解析用量”，确认预算后才发送描述给 AI。
3. 检查 AI 的目标理解和关键词。AI 默认每平台建议最多三组，可逐行编辑并手动追加；如果 AI 提出澄清问题，补充描述并重新解析，或切换为手动填写。
4. 检查后启动采集。默认每平台检查 50 个不同帖子候选，多关键词共用额度，每帖最多 50 条一级评论；不下载媒体。需要登录时在平台浏览器中扫码。
5. 在“批次与报告”查看新增帖子、评论、旧帖跳过数、重复评论、失败及结束原因；采集结束后显示完成提示。
6. 点击“预估本次需求分析用量”，检查服务商、模型、文字数量、预计输入、输出和请求次数，确认后后台分析。可以离开页面，之后回到本批次查看报告。
7. 需求榜按提及次数排序，可展开逐字原文证据、查看关联帖子，或复制报告、导出带批次和报告标识的 CSV。再次分析生成新版本。

研究模式直接保存到 `library/library.sqlite3`，与资料库共用内容；原普通采集功能和文件输出格式继续保留。每次采集独立归档，按采集时间区分，不新增帖子发布时间筛选。已有数据作为历史未分批内容用于去重；启动研究前会同步旧数据，来源文件有导入错误时先在资料库处理。首次升级前自动生成 `library/library.before-research-*.sqlite3` 数据库备份，不覆盖收藏、备注或标签。

去重使用平台和内容 ID，评论使用平台和评论 ID。旧帖再次命中只记录本次关联，跳过详情和评论请求，不复制正文；同标题不同 ID 的内容保留，仅显示疑似同标题提示。搜索分页还有重复页和最大页数保护，不为补足“新增数量”无限追加搜索。

报告只分析本批新增的标题、正文和已采评论。相同文字合并发送，但保留各自的证据映射。同一证据对同一需求只计一次；同一证据可涉及多个需求。程序根据证据计算提及次数、涉及帖子数和平台分布，点赞不当作需求人数；数字反映搜索样本，不代表市场总量。用户明确诉求与 AI 推测建议分开展示。B站研究模式保留完整简介。

AI Key 保存在被 Git 忽略的 `app/config/ai.local.json`，页面只返回是否已配置，不写入浏览器持久存储。该文件包含本机密钥，备份或分享项目时应排除。API 协议参考 [DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/)、[Kimi](https://platform.kimi.com/docs/api/chat)、[火山方舟](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1)。

预算完全在本地按 UTF-8 字节数保守估算，不调用远程计数接口；未捆绑匹配各模型的离线分词器，因此不宣称精确 token。实际以返回的 usage 为准，未返回 usage 的调用单独标记为估算。分块提取、归类、汇总共用一次确认预算，后续调用将超过预算时暂停，重新预估确认后继续。修改模型或配置使旧预算失效。超时和失败不自动重发，可能已在服务商计费；同配置重试保留已完成阶段，配置变化需要重新分析。

2026-11-09 修复输出截断：材料分块同时受输入空间、文字长度和单次输出容量约束。归类只让模型返回分组编号，说明和证据由程序保留，减少重复输出。重新预估截断的报告时仅缩小失败分块或后续批量，保留已完成提取与用量，不重抓数据，也不会在确认前调用模型；旧报告仍可从原失败版本继续。单次输出上限与整次任务预算是两个限制，单纯扩大整次预算不能解决一条响应写不完的问题。结束原因现区分长度限制、内容审核、工具调用和服务商中断；极小分块仍截断时会要求调整单次输出上限，避免原样反复计费。

归类编号校验兼容数字与字符串形式；组内重复编号会去重，无效编号不参与归类。跨组冲突及遗漏的候选独立保留，不猜测归属，不丢弃其证据。程序仍校验最终分区覆盖全部输入且每项恰好出现一次；发生校正时，页面、复制文本、摘要和 CSV 均标明部分同义需求可能分开计数。只记录编号异常数量，不将原始模型响应打印到日志。旧任务在归类阶段失败时，重新预估会沿用已完成的提取和局部分组，从全局归类或其已保存位置继续，确认前不会发送请求。

服务重启会将未完成任务标为中断，不自动重新采集或自动调用模型。首版没有跨批次累计需求榜、定时任务、视频语音转写、图片识别和弹幕分析。原项目的非商业学习许可证继续适用，商业使用需要解决授权。

## 数量与停止条件

输出配置增加了帖子数量上限、每帖一级评论上限（1–1000000）及停止条件。帖子上限按关键词／创作者计算，多关键词可能分别达到各自上限；其他平台可能按整页返回。

小红书的搜索模式可选择“没有更多帖子时停止”，不设置帖子数量上限，按平台返回的分页结束、空页或重复页停止；评论仍受单帖评论上限和子评论开关控制。其他平台／模式暂使用数量上限。

小红书搜索已修复整页凑数和最后一页丢弃问题。数据访问错误会作为错误结束，不再冒充正常无数据。模拟分页覆盖数量 1/25、最后一页、空页、重复页、起始页、多关键词及错误传播；隔离浏览器验证实际表单请求，未重复采集平台数据。

控制台“最近 500 行日志”是日志窗口容量，不是采集条数。2026-11-05 此次核对的文件为 40 篇帖子、359 条评论。

平台浏览器启动修复：B站、微博、知乎、贴吧、快手的标准模式已改为使用本部署配套 Chromium，不再强制使用系统 Chrome。七个平台的持久化浏览器启动均已通过本地测试，子进程异常退出也会保留错误状态。以上修复已在当前后台服务应用。

## 大任务请求频率

数量上限已提高到一百万。默认选择“自动：大任务降速”：帖子上限达到 10000、预计帖子数×每帖评论上限达到 10000，或小红书搜索选择无更多数据模式时，间隔至少 5 秒；默认每 100 次 API 请求休息 60 秒。选择“始终使用低频模式”可提前启用这套策略。间隔、休息次数及休息时长均可在界面修改，任务并发固定为 1。

逐 API 请求间隔和定期休息目前作用于小红书客户端；其他平台使用提高后的页面／评论间隔，不声称拥有相同的逐请求限速。媒体文件下载不纳入 API 请求计数。

小红书临时错误使用有次数限制的指数退避。HTTP 401/403/429、账号或 IP 限制及验证码会停止该客户端后续请求；429 的 Retry-After 提示写入日志，不自动换 IP 或持续重试。用户处理登录／验证或等待平台指定时间后，才手动重新启动。降速不保证不会封禁，也不能保证平台提供指定数量的数据。

百万条等长期任务建议使用 JSONL 或 SQLite，避免整个 JSON 文件反复重写。测试使用虚拟时钟、本地模拟 HTTP 和拦截启动请求的浏览器，已验证自动降速阈值、并发请求间隔、定期休息、2/4 秒递增退避、限制后零重试、百万数量校验及实际表单参数；未执行大规模采集。

## 数据资料库

主页新增显眼的“打开数据资料库”入口，点击打开独立页面；原控制台的文件弹窗入口与底部作者介绍／社交链接栏已经移除。详情在资料库页面内展开，返回后保留筛选条件。

已提供：

- 关键词包含／排除、平台、内容类型、来源关键词、发布日期、点赞／收藏／评论数、本地图片和自定义标签筛选。
- 24 条一页的图文卡片、排序、游标翻页、本地缩略图；原图和视频按需加载。
- 全文详情、关联评论（每次加载 50 条）、原文链接、收藏、隐藏、标签和备注。
- 对全部匹配结果流式导出 CSV，包含正文和整理备注；不是只导出当前页。

现有 JSON、JSONL、CSV、XLSX 中的 contents/comments 文件及默认的 `app/database/sqlite_tables.db` 可以导入。数据库保存于 `library/library.sqlite3`，缩略图缓存在 `library/thumbnails`。原始采集文件与媒体目录保持不变；收藏和备注单独保存，重新导入不会覆盖。

资料库每分钟检查数据文件变化；JSONL 以已读位置追加导入，SQLite 按更新时间增量扫描。图片目录自动检查周期为五分钟，点击“同步新数据”会主动检查图片。写入中的不完整文件会稍后重试。删除原文件不会自动删除已导入的索引内容，避免误删整理记录；媒体文件仍需保留以便显示。

中文两个字的词使用二元索引，较长词使用三元索引；单字搜索需要更广泛扫描，数据多时应搭配平台、日期等筛选。列表和评论不会整库传到浏览器，JSON 原始数组也使用流式解析。但全量导入和复杂筛选耗时仍取决于实际数据与硬件，未宣称已完成百万条压测。
